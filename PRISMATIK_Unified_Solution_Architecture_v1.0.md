# Part A. Consolidated Vision and Invariants

## 1. Executive Synthesis

PRISMATIK is a multi asset market intelligence and quantitative decision operating system. Its differentiator is not data breadth, not chart quality, and not model sophistication. Its differentiator is **the ability to prove what it said, why it said it, and what it knew at the moment it said it**.

Every architectural choice in this document flows from that single claim. Data breadth is commodity and can be bought. Chart rendering is commodity and can be adopted. Forecasting models are commodity and are given away by Amazon, Google, and academic labs. What cannot be bought or downloaded is a platform where a backtest run in July 2026 can be re executed byte for byte in July 2029, on a different machine, and produce an identical signed manifest, with every input traceable to a provider endpoint and a retrieval timestamp.

That capability is the product. Everything else is a delivery vehicle for it.

The corollary governs the open source posture, and it is unchanged from v0.4 but stated more sharply here:

> **Own every mechanism that could silently invalidate a reproduction claim. Adopt everything else.**

This is a stricter test than v0.4's "own every load bearing trust boundary," and it reclassifies three components. A trading calendar library looks like commodity infrastructure until you notice that calendars are shipped as code, revised in point releases, and silently change which bars a backtest sees. A tokenizer codebook looks like a model detail until you notice that changing it changes every downstream feature. A conformal calibrator looks like a statistics utility until you notice that it is the only thing standing between a transformer's raw quantile output and a user reading it as a probability. All three are now owned, versioned, content addressed artifacts under Section 12.

## 2. The Seven Invariants

These are extracted from the four predecessor documents, deduplicated, and promoted to testable form. Each has a CI gate named in Section 27. An invariant without a gate is an aspiration, and this platform has enough aspirations already.

### I1. Evidence Precedes Conclusion

No conclusion surface (opportunity card, forecast, score, ranking, alert) may render without a resolvable evidence chain terminating in raw records with provider identity and retrieval timestamps.

*Gate:* `test_no_orphan_conclusions` walks every aggregate that implements `Concludes` and asserts `evidence().is_nonempty()` and every `EvidenceRef` resolves.

### I2. Probability, Never Prophecy

Model output crosses the IPC boundary only as a distribution, interval, calibrated probability, ranking, or scenario set, never as a scalar point estimate without an accompanying uncertainty band and calibration record.

*Gate:* the `ModelPrediction` type has no public constructor that omits `CalibrationRecord`. This is enforced by the type system, not by review.

### I3. Determinism Under Seed

Identical inputs plus identical seed plus identical pinned artifact set produce byte identical outputs, on any machine, at any future date, until the pinned artifacts are explicitly rotated.

*Gate:* `dst_replay_suite` re runs a corpus of seeds and diffs TRACE level logs, following the pattern proven by the S2 storage team, who caught non determinism by comparing trace logs byte for byte across reruns of the same seed.

### I4. Structural Capability Enforcement

What a strategy, plugin, tool, or model may do is enforced by the runtime through capability tokens, not by convention, documentation, or code review.

*Gate:* `test_backtest_denies_network` asserts a strategy compiled with `can_access_network: false` cannot reach a socket even when its code attempts to, because the WASM host provides no such import.

### I5. Point In Time Correctness

No feature, model input, or backtest observation may include information with an `event_time` later than the simulated clock, including information laundered through a pretrained model's corpus.

*Gate:* `test_pretraining_cutoff_denial` plus the temporal join property tests in Section 16.

### I6. Fail Closed on Staleness

Automation that depends on timely data halts rather than degrades. Staleness is a hard deny, not a warning, anywhere an order intent is in scope.

*Gate:* `stale_data` check in the pre trade catalog, plus chaos tests that freeze a provider feed and assert automation stops.

### I7. Tamper Evident Audit

Sensitive operations write to an append only, hash chained ledger where any retroactive edit is detectable without trusting the storage layer.

*Gate:* `test_audit_chain_integrity` verifies the Merkle inclusion proof for a random sample of historical entries on every CI run and on every application start.

## 6. New Component Recommendations

Each entry below states what it is, what gap it closes, the license posture as verified on 2026-07-24, the assigned integration mode, and the specific risk that must be tracked.

### 6.1 LanceDB and the Lance Format — Mode A, Adopt

LanceDB is an embedded retrieval engine whose core is written in Rust and built on Lance, a columnar format designed for machine learning workloads and fast random access. Both the database and the underlying format are designed to be easy to use, scalable, and cost effective. It offers columnar storage built on the Lance format, native Python, Node.js, and Rust SDKs, and integrations with Apache Arrow, Pandas, Polars, and DuckDB. It supports IVF-PQ, IVF-Flat, HNSW-PQ, BTree, Bitmap, and full text indexes, ACID transactions with automatic versioning, SQL query via DataFusion integration, and zero copy operations through Arrow. It is Apache 2.0 licensed.

**Closes:** G06. Also materially improves the offline feature store.

**Why this and not Qdrant, Milvus, or pgvector.** Three reasons, in priority order. First, it runs in process, which matches the local first doctrine of v0.1 §4.4 and avoids shipping a server to a desktop user. Second, it is Arrow native, so the offline feature store, the tokenized series views from v0.3 §4, and the embedding index share one memory representation with no serialization tax. Third, and decisively, **automatic dataset versioning**. A reproducibility manifest can pin a Lance dataset version and a future reproduction reads exactly the rows that existed at manifest time. With pgvector you would build that yourself, badly.

**Assigned role.** `prismatik-analog-store` wraps it. Three tables: `analog_embeddings` (TSFM hidden states plus modality, codebook version, event time), `evidence_index` (filing and news text embeddings for retrieval augmented AI), `regime_prototypes` (labelled regime centroids for the secondary filters required by v0.3 §5).

**Risk to track.** The Lance format is young relative to Parquet. Mitigation: Lance is a *derived* store only. Every embedding is recomputable from Parquet raw plus a pinned model artifact. If Lance is abandoned, PRISMATIK loses an index, not data. Record this explicitly in the component manifest as `recovery_class: derived`.

### 6.2 Apache DataFusion — Mode A, Adopt

An embeddable, extensible SQL query engine in Rust with a physical plan optimizer, already a transitive dependency through LanceDB.

**Closes:** part of G11.

**Assigned role.** Two jobs. First, it is the execution substrate for the Strategy DSL's data access layer: universe selection, filters, and windowed aggregations compile to DataFusion logical plans rather than a bespoke evaluator. Second, it is the point in time query enforcement point, because a temporal correctness rule expressed as a plan rewrite rule cannot be forgotten by a strategy author, whereas one expressed as a convention will be.

**Risk to track.** Version churn is significant. Pin exactly, upgrade deliberately, and keep the golden query suite in Section 27.4 as the regression net.

### 6.3 tauri-specta and Specta — Mode A, Adopt with pinning discipline

tauri-specta generates TypeScript bindings directly from Rust commands and events. Commands are annotated with `#[specta::specta]` and collected using `tauri_specta::collect_commands![]`. The library builds a typed invoke handler and emits a bindings file, and the frontend imports it and calls commands with fully inferred TypeScript signatures, ensuring end to end type safety between Rust and TypeScript without manually duplicating types.

**Closes:** G05.

**Why Specta and not ts-rs or typeshare.** The Specta maintainers state the tradeoff plainly: ts-rs deals with types individually, which makes it impossible to export a type and all the other types it depends on, and typeshare statically analyzes Rust files, which loses information and lacks compatibility with types from other crates. PRISMATIK's IPC surface carries deeply nested domain aggregates spanning a dozen crates. Per type export is not viable.

**Risk to track, and it is real.** tauri-specta v2 requires Tauri v2 and Specta v2, and version pinning is critical to avoid breaking changes during the RC phase. Specta v2 has been in release candidate for an extended period, with dependent crates pinning exact RC versions such as `specta = "=2.0.0-rc.25"`. **Mandate:** pin with `=` exact version syntax, never a caret range, and register the RC status as an explicit accepted risk in the component manifest with a quarterly review trigger. If Specta v2 has not reached stable by Phase 3, open the ADR to evaluate a hand rolled JSON Schema pipeline as the fallback.

**Also evaluate:** TauRPC, which layers a trait based bidirectional IPC API over Specta and was inspired by tarpc. Worth a prototype at Phase 1 if command surface growth makes raw `collect_commands!` unwieldy.

### 6.4 wasmtime plus Extism — Mode A for wasmtime, Mode B candidate for Extism

**Closes:** G04.

wasmtime is the Bytecode Alliance WebAssembly runtime with WASI capability based sandboxing. Extism is a plugin framework layered on it that provides a unified guest and host API and uses wasmtime as its runtime, where WASM by default has no access to the host file system but through WASI can be given sandboxed access to a predefined list of allowed directories. The Extism Rust SDK emits plugin log messages as tracing events in the host application.

**Assigned role.** `prismatik-plugin-host`. Three plugin classes, each with a distinct capability set: indicator plugins (pure compute, no imports beyond math), data transform plugins (read scoped Arrow batches, no network), and visualization plugins (emit plot primitives only). No plugin class receives network, filesystem, clock, or entropy imports. Time and randomness come from the Determinism Kernel through explicit host functions, which is what makes plugin execution reproducible.

**Risk to track, and this one is serious.** wasmtime has shipped sandbox escape and out of sandbox load advisories during 2026, including RUSTSEC-2026-0095, a Winch compiler backend issue allowing sandbox escaping memory access, affecting versions below 36.0.7, 37.0.0 through 42.0.1, and 43.0.0, with a CVSS 4.0 vector of network attack, low complexity, high confidentiality, integrity, and availability impact including scope change, and a separate advisory where the f64.copysign operator on x86-64 with AVX could load eight more bytes than necessary, producing an uncaught segfault when signals based traps are disabled, or an out of sandbox load when guard pages are disabled.

**Therefore, three hard configuration rules, enforced in code and asserted in a unit test:**

1. Use the Cranelift backend. **Winch is prohibited.**
2. `signals-based-traps` MUST remain enabled. Guard pages MUST remain enabled.
3. The wasmtime version MUST be pinned and MUST be checked against RustSec on every CI run with `cargo deny` advisories as a blocking gate, not a warning.

A sandbox you have not configured correctly is a liability with a marketing story attached.

**Related and worth monitoring:** Wassette, described as a security oriented runtime that runs WebAssembly Components via MCP, and hyper-mcp, a fast, secure MCP server that extends its capabilities through WebAssembly plugins. Both sit at the exact intersection of PRISMATIK's plugin host and AI tool gateway. Mode E, reference only, for now, with a Phase 6 re evaluation.

### 6.5 rmcp, the official Rust MCP SDK — Mode A, Adopt

The official Rust Model Context Protocol SDK, built on the tokio async runtime, providing the rmcp core crate and rmcp-macros for generating tool implementations, with support for tools, resources, prompts, sampling, roots, logging, completions, notifications, subscriptions, tasks, caching, and OAuth. The transport layer is pluggable, and any type implementing the Transport trait can be used, with an IntoTransport helper providing automatic conversions.

**Closes:** G16.

**Assigned role.** The `prismatik-ai-tools` crate implements both sides. As a **server**, PRISMATIK exposes its eleven controlled tools from v0.2 §4 to external MCP clients, gated by the same `ToolGateway` trust levels. As a **client**, it consumes signed third party MCP servers, notably the Unusual Whales MCP surface referenced in v0.1 §40.

The pluggable transport is architecturally important: it lets PRISMATIK run an MCP server over an in process transport for the embedded AI analyst and over stdio or HTTP for external clients, with **one** gateway implementation and therefore one place where trust levels are enforced. Two gateways would be two places to get it wrong.

**Risk to track.** Version velocity is high, with releases through 0.12 and beyond and a documented migration path to 1.x. Pin exact, and keep the tool descriptor schema in PRISMATIK's own types so an SDK bump cannot silently change a tool's declared trust level.

### 6.6 MAPIE — Mode C, Isolated Sidecar

A scikit-learn compatible library for estimating prediction intervals and controlling risks based on conformal prediction, implementing peer reviewed algorithms that are model and use case agnostic with theoretical guarantees under minimal assumptions on the data and the model. It is free and open source under the BSD-3-Clause license. It computes prediction intervals for regression and time series by estimating model uncertainty on a conformalization dataset, and supports testing distribution shifts and monitoring exchangeability assumptions. Its time series regressor supports EnbPI and ACI, adaptive conformal inference, with conformal scores updatable as new observations arrive.

**Closes:** G03. This is the single most important addition in Part B.

**Why it matters more than it looks.** v0.1 §12.5 and v0.3 §6.3 both mandate a calibration pipeline and both decline to say what calibration means. Meanwhile v0.3 §6.3 correctly observes that TSFM quantile outputs are rarely well calibrated out of the box. Without a named method this is a hole directly under Invariant I2, the single most legally exposed claim the product makes. Conformal prediction closes it with distribution free finite sample coverage guarantees, which is exactly the property you want when a regulator or a customer asks what "seventy percent confidence" means.

The financial specific subtlety: conformal prediction's standard guarantee assumes exchangeability, and financial returns are emphatically not exchangeable. This is why the choice is specifically **ACI, adaptive conformal inference**, which adjusts the target quantile online in response to realized coverage error and does not require exchangeability. MAPIE's inclusion of exchangeability testing on its roadmap is a further signal that the library takes the assumption seriously rather than papering over it.

**Assigned role.** `prismatik-calibration-worker`, a Python sidecar. Input: an Arrow table of held out predictions and realizations. Output: a signed `CalibrationRecord` (Section 17.3) written back through the repository port. It never touches live data, never sees a credential, and cannot emit an audit event.

**Why a sidecar and not a Rust port.** Conformal prediction is a small amount of arithmetic wrapped around a large amount of statistical subtlety. The arithmetic is trivial to reimplement; the subtlety is not, and getting it wrong produces intervals that look right and are not. Use the peer reviewed implementation as the reference, keep golden vectors, and revisit a native Rust implementation only if the sidecar becomes a latency problem, which it will not because calibration is a batch operation on a schedule.

**Also assessed:** crepes, which implements standard and Mondrian conformal classifiers and standard, normalized, and Mondrian conformal regressors and predictive systems, turning predictions into well calibrated p values and cumulative distribution functions. Its Mondrian categorization is directly useful for PRISMATIK's regime conditioned calibration, because a Mondrian conformal regressor divides the object space into non overlapping categories and forms a conformal regressor for each, which is exactly the shape of "calibrate separately per volatility regime." Adopt crepes alongside MAPIE in the same sidecar. TorchCP is a further option for PyTorch native scoring, noted as providing six training algorithms, seventeen scores, and ten predictors, and is deferred to Phase 8.

### 6.7 Amazon Chronos, Google TimesFM, and the TSFM License Trap — Mode A for artifacts, Mode E for code

**Amends:** v0.3 in a way that materially de risks it.

v0.3 builds its entire TSFM design around Kronos. Kronos is a strong choice on the merits: a family of decoder only foundation models pretrained specifically on financial K line sequences, using a specialized tokenizer that quantizes continuous OHLCV data into hierarchical discrete tokens, released under the MIT License, trained on over twelve billion K line records from forty five global exchanges, and accepted by AAAI 2026.

But v0.3 treats Kronos as the only candidate, and three findings argue for a plural registry from day one.

**Finding one, the license trap.** Moirai is licensed under CC BY-NC 4.0, which prohibits commercial use without a commercial license from Salesforce, and it must not be deployed in revenue generating production pipelines without confirming licensing compliance, whereas Chronos, TimesFM, and Lag-Llama are Apache 2.0 and commercially unrestricted. Moirai is frequently top ranked on public leaderboards, including ranking highly on GIFT-Eval among non data leaking models with strong in distribution and zero shot performance, trained on the LOTSA dataset of twenty seven billion observations across nine domains. A researcher benchmarking in good faith will reach for it, get the best numbers, and hand Mythos Systems a licensing problem inside a commercial product. **Therefore: the model registry MUST enforce license class at registration, and CC BY-NC artifacts MUST be rejected with an explicit error naming the license, not silently permitted with a warning.** This is a five line check that prevents a category of problem no amount of documentation will.

**Finding two, maintenance asymmetry.** Kronos is a research repository. Public tracking as of mid 2026 records its last commit at roughly one hundred days prior, and the repository itself carries maintainer warnings worth quoting in the intake record: the finetune code comments were generated by an AI assistant and may contain inaccuracies, and the included backtest is a demo that skips transaction costs, slippage, and risk factor neutralization. Chronos by contrast has Chronos-2 released with zero shot support for univariate, multivariate, and covariate informed forecasting, achieving best performance on fev-bench, GIFT-Eval, and Chronos Benchmark II among pretrained models, with SageMaker JumpStart and AutoGluon deployment paths, and a distilled Chronos-Bolt variant that is substantially faster and more memory efficient, with the family spanning roughly nine million to seven hundred ten million parameters.

**Finding three, the covariate gap.** Kronos consumes OHLCV. PRISMATIK's most differentiated signals are *not* OHLCV: they are options flow, implied volatility surfaces, filing events, and Commitments of Traders positioning. Chronos-2's covariate informed forecasting and Moirai's native covariate handling address a need Kronos structurally does not.

**Ruling.** `prismatik-tsfm` ships as a **plural registry** from Phase 5, not a Kronos wrapper.

| Chronos-Bolt | Apache-2.0 | Default general forecaster, latency tier | 5 |
| Chronos-2 | Apache-2.0 | Covariate informed forecasts, accuracy tier | 5.5 |
| TimesFM 2.5 | Apache-2.0 | Long horizon, sixteen thousand token context | 6 |
| Lag-Llama | Apache-2.0 | Probabilistic baseline for calibration comparison | 5 |
| Moirai / Moirai-2 | **CC BY-NC 4.0** | **Research benchmarking only, registry hard denies at commercial registration** | never in product |

The `SeriesTokenizer` trait from v0.3 §3.1 already accommodates this: Kronos supplies one codebook implementation, Chronos supplies another with different bin semantics, and the reconstruction MAE disclosure requirement applies identically to both. **v0.3 needs no structural change to support plurality, which is a compliment to its design.**

One operational note from the Kronos documentation that belongs in the runtime: Kronos-mini pairs with the 2k tokenizer and supports a 2048 context while the small and base models use the base tokenizer with a 512 context, and mismatching tokenizer to model causes loading to misbehave. The tokenizer and model version pairing MUST therefore be a validated invariant in the artifact manifest, not a convention.

### 6.8 barter-rs — Mode E, Validation and Design Reference

An algorithmic trading ecosystem of Rust libraries for live trading, paper trading, and backtesting, comprising Barter (engine with state management), Barter-Instrument (exchange, instrument, and asset structures), Barter-Data (public market data streaming via a MarketStream interface), Barter-Execution (private account data and order execution via an ExecutionClient interface), and Barter-Integration (REST and WebSocket frameworks). It provides plug and play Strategy and RiskManager components, a standalone order management system, trading summaries with PnL, Sharpe, Sortino, and drawdown metrics, the ability to toggle algorithmic trading from an external process while still processing market and account data, and an EngineState replica manager that processes the Engine AuditStream to support non hot path monitoring components.

**Do not adopt as a dependency.** It occupies exactly the trust boundaries PRISMATIK must own: strategy runtime, risk management, order management, portfolio accounting.

**Adopt one idea, and it is a good one.** The **AuditStream plus EngineState replica** pattern. In barter's model the audit stream is not a side effect written after the fact; it is the primary output, and monitoring surfaces including the UI are *replicas* rebuilt by replaying it. That inverts the usual relationship, where audit is a log the application writes if it remembers to.

For PRISMATIK this is close to decisive, because Invariant I7 is much easier to guarantee when audit is structurally upstream of state rather than downstream of it. Section 14.2 adopts it: the Audit Ledger is the write path, and the desktop UI's portfolio and order views are replicas derived from it. A UI that disagrees with the ledger is then a detectable divergence rather than an invisible one.

Also worth mining: the split of `barter-instrument` as a standalone crate for exchange, instrument, and asset structures validates PRISMATIK's separation of canonical identity into the Determinism Kernel rather than scattering it across domain crates.

### 6.9 madsim, turmoil, and Deterministic Simulation Testing — Mode A, Adopt

**Closes:** G01 and G13. This is the mechanism v0.1 through v0.3 were missing.

MadSim is a Rust async runtime similar to tokio but with deterministic simulation, borrowing its main idea from FoundationDB, where the simulator amplifies randomness, creates chaos, and injects failures, revealing hidden bugs that can then be deterministically reproduced until fixed. Implementing deterministic simulation is difficult because all I/O related interfaces must be mocked and all uncertainties eliminated. It simulates network conditions, time progression, and failure injection in a fully deterministic environment, allowing code to run in both real and simulated environments without changes. turmoil provides deterministic execution by running multiple concurrent hosts in a single thread and introduces network hardship controlled manually or by a seeded RNG. The technique was popularized by FoundationDB and has since been adopted by TigerBeetle, Resonate, and Turso's Rust rewrite of SQLite.

**The finding that changes PRISMATIK's design, not just its test suite.** Runtime level determinism is insufficient. The S2 engineering team documented this precisely: turmoil's approach was not comprehensive enough for time and randomness across arbitrary dependencies, including the subtlety that Rust HashMaps are randomized for denial of service prevention, so they turned to MadSim's libc symbol overrides, producing a derived crate whose rand module overrides getrandom, getentropy, and CCRandomGenerateBytes, and whose time module overrides clock_gettime. Their verification method is the one PRISMATIK should copy verbatim: a meta test in CI that reruns the same seed and compares TRACE level logs, achieving conformity down to the last bytes on the wire, so a failing seed from CI reproduces locally.

An independent 2026 writeup reaches the same conclusion and states the design rule cleanly: the seed pins the simulator's choices, not your program's, so if code calls Instant::now it sees real wall clock time and the test stops being deterministic, and the same applies to getrandom, quanta, rdtsc, or anything fetching entropy or time out of band, because the Rust ecosystem has so many transitive crates pulling time and randomness out of band that determinism needs a libc level seam, not just a runtime level one. The practical rule is to pass a Clock and an Rng in by trait, swap them for deterministic versions in tests, and never call Instant::now from anywhere cargo test reaches, which does not catch every leak, since transitive HashMap iteration still bites, but is the cheapest eighty percent of the win.

**This validates and sharpens v0.2 §1.2.** `StrategyContext` already carries `DeterministicClock` and `SeededRng`. Correct instinct. But v0.2 confines that discipline to strategies, and the leak surface is the entire process: every provider adapter, every pipeline task, every cache eviction, every retry backoff. Section 12 therefore promotes clock and entropy injection from a strategy convenience to a **workspace wide lint enforced rule**, with `std::time::Instant::now`, `SystemTime::now`, `rand::thread_rng`, and unseeded `HashMap`/`HashSet` construction all banned outside the kernel crate.

**Assigned role.** `prismatik-determinism` provides the traits. madsim provides the simulated runtime for the `dst_replay_suite`. Every reproducibility claim in a manifest is backed by a passing DST run, not by hope.

### 6.10 Supply Chain Toolchain — Mode A, Adopt as CI Gates

**Closes:** G15.

The consensus 2026 Rust toolchain, verified across multiple independent sources including Microsoft's Rust engineering guidance:

| Tool | Role | PRISMATIK gate |
|---|---|---|
| `cargo audit` | checks dependencies against the RustSec advisory database and warns about known vulnerabilities or yanked versions | Blocking on any advisory |
| `cargo deny` | enforces policies on licenses, duplicate dependencies, and banned crates | Blocking; license allowlist |
| `cargo vet` | Mozilla's tool requiring human reviewed audits of third party crates, integrating with SLSA, where each crate either has an entry in audits.toml or is covered by a trusted organisation's published audit set | Blocking for crates in the trusted core |
| `cargo auditable` | embeds dependency data in binaries for at rest auditing | Release builds |
| `cargo cyclonedx` | SBOM generation | Every release artifact |
| cosign / Sigstore | keyless signing where developers authenticate through OIDC and receive a short lived certificate, with Fulcio as certificate authority and Rekor as the transparency log recording signing events so they cannot be tampered with after the fact | Every release artifact |
| SLSA provenance | provenance attests to build integrity while a cosign signature attests to artifact identity, and generating provenance is only half the model, the other half being verification at the point of consumption, without which provenance generation is a logging exercise rather than a security control | Generated and **verified** by the updater |

**Calibration on cargo vet.** Independent guidance is consistent that cargo-vet is a high friction control best suited to security critical projects such as cryptography libraries, firmware, and financial systems, while for most production services cargo-deny with advisory enforcement and a reviewed Cargo.lock is the right baseline, and that cargo-vet is most valuable for organizations with strict supply chain requirements in government, finance, and infrastructure. PRISMATIK is a financial system with a one engineer maintenance budget, so the ruling splits the difference: **cargo vet is mandatory for crates inside the trusted core and the Determinism Kernel, and cargo deny alone governs the rest.** Import the Mozilla, Google, and Bytecode Alliance audit sets to avoid re auditing serde by hand.

**One caveat that belongs in the doctrine, because v0.1 §28 leans on SBOMs.** The cargo-auditable maintainers state it directly: SBOMs do not prevent supply chain attacks and cannot even be used to assess the impact of such an attack after discovery, because any malicious library worth its bytes will remove itself from the SBOM. SBOMs are a compliance and inventory artifact. The controls that actually resist an attack are the reviewed lockfile, cargo vet, artifact signing, and provenance verification at install time. Write that distinction into the security documentation so nobody mistakes an SBOM for a defense.

**Optional hardening for the enterprise profile:** redirecting all crate resolution through a private registry via .cargo/config.toml and blocking direct crates.io access, plus `cargo vendor` for air gapped builds, which the Disconnected Research Environment profile in v0.1 §25.1 requires anyway.

### 6.11 Market Calendar Sources — Mode D, Compatibility Adapter, with a warning

**Closes:** G07.

`exchange_calendars` is the maintained successor to the unmaintained quantopian `trading_calendars`, and `pandas_market_calendars` mirrors all calendars from exchange_calendars, adding over fifty calendars, supports intraday breaks for Asian markets with lunch sessions and futures markets with processing breaks, provides a framework for market interruptions, and as of v5.0 uses the zoneinfo standard.

**The warning, and it is the whole reason this section exists.** The pandas_market_calendars changelog contains a line that should be printed and taped to a wall: calendars are package shipped code, not live server provided data. The same changelog documents a single pull request that fixed CME calendar regressions for Globex holidays, fixed income hours, agriculture hours, and historical equity hours, fixed NYSE early close post market handling, BSE and NSE aliases and the 2024 election holiday, NYSE rollback behavior, and EUREX regular open and close hours.

Read that as an engineer, not as a user. A backtest executed before that release and re executed after it will produce different results, from identical code, identical data, and an identical seed, because the set of valid trading minutes changed underneath it. That is a silent violation of Invariant I3, and no amount of seed pinning catches it.

**Ruling.** PRISMATIK MUST NOT call a calendar library at runtime. Instead:

1. A build time job materializes the full session schedule for every supported venue into a **content addressed calendar artifact** (Parquet, one row per session with open, close, breaks, early close flags, and interruptions).
2. The artifact is signed and versioned.
3. Every reproducibility manifest pins `calendar_artifact_hash`.
4. The runtime reads the pinned artifact only, and a calendar upgrade is an explicit, reviewed, invalidating event that propagates through the lineage model exactly like a tokenizer codebook change.

Cross validate against QuantLib's calendar module, which v0.4 already adopts as a conformance oracle. Two independent sources disagreeing about a session is a data quality event, not a coin flip.

### 6.12 Symbology — Mode D plus internal authority

**Closes:** G08.

OpenFIGI provides free, open, permanently assigned financial instrument global identifiers with a public mapping API, which is the right external anchor for equities, ETFs, and options contracts. Crypto has no equivalent authority, which is why v0.1 §9.2 makes CoinGecko the canonical crypto aggregation provider.

**Ruling.** `prismatik-symbology` in the Determinism Kernel owns an internal `AssetId` that is the only identifier domain crates ever see. External identifiers (FIGI, CUSIP where licensed, ISIN, ticker plus MIC, CoinGecko id, contract address plus chain id) are *attributes with validity intervals*, never keys. A ticker that was `FB` in 2021 and `META` after must resolve correctly for a 2021 backtest, which is only possible if the mapping is bitemporal. Store `(asset_id, identifier_type, identifier_value, valid_from, valid_to, source, retrieved_at)` and resolve as of the simulated clock, never as of now. This is the concrete implementation of the temporal knowledge graph that v0.1 §37.11 files as a future advancement; it is not a future advancement, it is a Phase 2 requirement, because equity backtests are wrong without it.

### 6.13 OpenLineage — Mode D, Schema Alignment Only

**Closes:** G14.

v0.2 §8 defines a bespoke `Lineage` struct. It is well designed. But OpenLineage is the emerging open standard for dataset and job lineage events, and adopting its *event schema* costs nearly nothing while buying interoperability with Marquez, DataHub, and enterprise data catalogs that Enterprise On-Prem customers will already run.

**Ruling.** Keep the internal `Lineage` type exactly as v0.2 defines it. Add a projection: `impl From<&Lineage> for OpenLineageRunEvent`. Emit OpenLineage events to an optional sink in the Team Cloud and Enterprise profiles only. The desktop profile emits nothing. This is Mode D, a compatibility adapter, and it must never become a dependency of the domain.

### 6.14 governor — Mode A, Adopt

**Closes:** G10.

v0.1 §10.5 and v0.2 Part III specify a rate and budget governor in detail and never name an algorithm. The `governor` crate implements GCRA, the generic cell rate algorithm, which is the correct choice over a naive token bucket because it is allocation free, provides exact next permit timing rather than a boolean, and composes cleanly with keyed limiters for per provider and per endpoint quotas.

The "exact next permit timing" property is not a micro optimization. The rate budget UI specified in v0.2 §11.3 needs to tell a user *when* a blocked request will proceed, and a token bucket cannot answer that question without extra bookkeeping. GCRA answers it natively.

## 8. Licensing and Commercial Posture

v0.4's Green, Amber, Red classification is retained. Three amendments.

**Amendment one: a fourth class for model artifacts.** Model weights are not code and their licenses do not behave like code licenses. CC BY-NC 4.0 is the specific hazard, because it is common in academic model releases, it looks permissive to a casual reader, and it prohibits exactly what PRISMATIK does. The model registry enforces this in code:

```rust
/// License classes for model artifacts. Distinct from code license classes
/// because model weight licenses carry non-commercial and field-of-use terms
/// that code licenses generally do not.
#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum ArtifactLicenseClass {
    /// Apache-2.0, MIT, BSD. Distributable inside a commercial product.
    PermissiveCommercial,
    /// Requires attribution in-product but is otherwise unrestricted.
    AttributionRequired,
    /// Non-commercial (CC BY-NC and relatives). Research registry only.
    /// Registration into a commercial-profile registry is a hard deny.
    NonCommercial,
    /// Custom or vendor terms requiring individual legal review before use.
    RequiresLegalReview,
}
```

**Amendment two: attribution is a build artifact, not a task.** Lightweight Charts and several adopted packages require notice retention. Notices MUST be generated by `cargo about` and the equivalent Node tooling into an in application "Open Source Notices" surface, and the build MUST fail if a dependency lacks a resolvable license text. Manual notice maintenance in a one engineer operation has a predictable failure mode.

**Amendment three: PRISMATIK's own license boundary.** The trusted core, the Determinism Kernel, the strategy IR, the risk policy, the evidence graph, and the design system are proprietary. The **plugin SDK, the chart contracts, the indicator trait, and the manifest schema SHOULD be published under Apache-2.0.** Publishing the contracts and keeping the implementation is the posture that builds an ecosystem without giving away the product, and it makes the manifest schema citable by third parties who need to verify a PRISMATIK research artifact, which is the point of Section 14.4.

## 12. The Determinism Kernel

This section closes G01 and G13 and is the largest single addition in v1.0.

### 12.1 The Problem, Stated Precisely

v0.1 §4.7 promises reproducibility. v0.2 §18 specifies a manifest that records a seed. v0.3 §6.4 extends it. None of them address the fact that in a Rust application of this size, non determinism enters through at least seven doors:

1. `Instant::now` and `SystemTime::now` called anywhere in the process or in any transitive dependency.
2. `getrandom` / `getentropy` at the libc level, invoked by crates that never advertise it.
3. `HashMap` and `HashSet` iteration order, randomized by default for denial of service resistance.
4. Task scheduling order in a multi threaded tokio runtime.
5. Floating point reduction order under Rayon parallelism.
6. Network and disk timing affecting retry, timeout, and cache eviction paths.
7. Silently upgraded reference data, notably calendars and tokenizer codebooks.

A seed in a manifest addresses door one partially and nothing else. The Determinism Kernel addresses all seven.

### 12.2 Core Traits

```rust
//! prismatik-determinism
//!
//! The single source of time, entropy, and ordering for the entire platform.
//! No other crate in the workspace may call `std::time::Instant::now`,
//! `std::time::SystemTime::now`, `rand::thread_rng`, or construct a
//! `HashMap`/`HashSet` with the default `RandomState`. This is enforced by
//! a workspace lint (`clippy.toml` disallowed paths) and by a CI grep gate.
//!
//! Rationale: reproducibility claims are only as strong as the weakest
//! ambient-nondeterminism leak in the process, including leaks inside
//! transitive dependencies. Injecting time and entropy by trait is the
//! cheapest control that closes the majority of that surface.

use std::collections::HashMap;
use std::hash::BuildHasherDefault;
use time::OffsetDateTime;

/// Deterministic time source.
///
/// Three implementations exist and only three:
///   * `SystemClock`      - wall clock. Permitted ONLY in the outermost
///                          application shell and in ingestion, where it
///                          stamps `retrieved_at` on raw records.
///   * `SimulatedClock`   - advances only when the runtime advances it.
///                          Used by backtest, replay, and DST.
///   * `FrozenClock`      - fixed instant. Used by unit tests and by
///                          point-in-time feature materialization.
pub trait Clock: Send + Sync + 'static {
    /// Current logical time. In simulation this is the simulated instant,
    /// never the host wall clock.
    fn now(&self) -> OffsetDateTime;

    /// Monotonic tick count since run start. Used for durations and for
    /// ordering, never for wall-clock arithmetic.
    fn monotonic_nanos(&self) -> u64;

    /// Sleep until the given logical instant. In simulation this yields
    /// to the scheduler and advances simulated time; it does not block.
    fn sleep_until(&self, deadline: OffsetDateTime) -> BoxFuture<'static, ()>;

    /// Identifies the clock in the reproducibility manifest.
    fn kind(&self) -> ClockKind;
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum ClockKind {
    System,
    Simulated,
    Frozen,
}

/// Deterministic entropy source.
///
/// Splittable by design: a child stream derived from a parent stream with a
/// stable label produces the same values regardless of the order in which
/// sibling streams are consumed. This is what makes parallel Monte Carlo
/// reproducible under Rayon, where completion order is not deterministic
/// but stream identity is.
pub trait Entropy: Send + Sync + 'static {
    /// Derive a labelled child stream. Same parent seed + same label
    /// always yields the same child, independent of call order.
    fn split(&self, label: &str) -> Box<dyn Entropy>;

    fn next_u64(&mut self) -> u64;
    fn next_f64_unit(&mut self) -> f64;

    /// Fill a buffer. Used for id generation; NEVER for cryptographic
    /// material. Cryptographic randomness comes from the OS CSPRNG in
    /// `prismatik-security` and is deliberately outside this trait,
    /// because key material must never be reproducible.
    fn fill_bytes(&mut self, dest: &mut [u8]);

    /// Root seed, recorded in the manifest.
    fn root_seed(&self) -> u64;

    /// Stable path of labels from root to this stream, recorded in the
    /// manifest so a specific stream can be replayed in isolation.
    fn stream_path(&self) -> &[String];
}

/// Deterministic hasher. All maps and sets that participate in any
/// computation whose output is observable MUST use this.
pub type DetHasher = BuildHasherDefault<rustc_hash::FxHasher>;
pub type DetMap<K, V> = HashMap<K, V, DetHasher>;
pub type DetSet<T> = std::collections::HashSet<T, DetHasher>;

/// The bundle every deterministic subsystem receives. `StrategyContext`
/// from v0.2 §1.2 is now a wrapper around this plus scoped data access,
/// rather than defining clock and rng itself.
pub struct DeterminismContext {
    pub clock: Arc<dyn Clock>,
    pub entropy: Box<dyn Entropy>,
    pub run_id: RunId,
    /// Every pinned artifact this run depends on. Populated at run start,
    /// frozen thereafter, and copied verbatim into the manifest.
    pub pinned: PinnedArtifactSet,
}

/// The complete set of external inputs whose change would alter results.
/// If it is not in here, it cannot influence a run. That is the invariant.
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct PinnedArtifactSet {
    pub calendar: ArtifactRef,
    pub symbology_snapshot: ArtifactRef,
    pub corporate_actions: ArtifactRef,
    pub codebooks: Vec<ArtifactRef>,
    pub models: Vec<ArtifactRef>,
    pub indicator_kernel_version: SemanticVersion,
    pub dataset_versions: Vec<DatasetVersionRef>,
}

/// A content-addressed, signed artifact reference.
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct ArtifactRef {
    pub artifact_id: ArtifactId,
    pub kind: ArtifactKind,
    pub version: SemanticVersion,
    /// BLAKE3 of the artifact bytes. Verified on load, every load.
    pub content_hash: ContentHash,
    /// Detached signature over `content_hash`. Dual scheme per §24.

}
```

### 12.3 Enforcement, Not Convention

Three mechanisms, all of which run in CI and fail the build.

**Mechanism one, a workspace lint.** `clippy.toml` at the workspace root:

```toml
# Any call to ambient time or entropy outside prismatik-determinism is a
# determinism leak. These are hard errors, not warnings.
disallowed-methods = [
  { path = "std::time::Instant::now",        reason = "use Clock::monotonic_nanos" },
  { path = "std::time::SystemTime::now",     reason = "use Clock::now" },
  { path = "time::OffsetDateTime::now_utc",  reason = "use Clock::now" },
  { path = "rand::thread_rng",               reason = "use Entropy::split" },
  { path = "rand::random",                   reason = "use Entropy" },
  { path = "uuid::Uuid::new_v4",             reason = "use IdFactory backed by Entropy" },
]
disallowed-types = [
  { path = "std::collections::HashMap",      reason = "use DetMap; RandomState iteration order is nondeterministic" },
  { path = "std::collections::HashSet",      reason = "use DetSet" },
]
```

The determinism crate itself carries a scoped `#![allow]`. Ingestion carries a narrow, reviewed allowance for `Clock::now` on the `SystemClock` only, because `retrieved_at` must be real wall clock time.

**Mechanism two, deterministic simulation testing.** `dst_replay_suite` runs the full ingest to feature to backtest to manifest path under madsim with a corpus of seeds, with network hardship, clock skew, and failure injection applied by the simulator. The verification method is trace comparison, following the approach the S2 team proved: rerun the same seed and diff TRACE level logs byte for byte. A divergence is a build failure with the failing seed printed, which makes it reproducible on a developer machine immediately.

**Mechanism three, the golden manifest corpus.** A set of committed manifests with known outputs. CI re executes each and asserts byte identical results. When a change legitimately alters output, the manifest is regenerated in the same commit with a mandatory changelog entry explaining what changed and why. This is the mechanism that catches door seven, silently upgraded reference data, because a calendar bump that changes a single session will fail the golden corpus loudly.

### 12.4 Session Calendar as a Pinned Artifact

```rust
/// Trading session authority. Implementations read a pinned, signed
/// artifact and never a live library or service.
///
/// Non-negotiable design constraint: upstream calendar libraries ship
/// sessions as versioned CODE, and point releases have historically
/// corrected years of past sessions across CME, NYSE, and EUREX. A
/// backtest that reads a calendar at runtime is therefore not reproducible

/// sessions into a content-addressed artifact converts a silent

pub trait SessionCalendar: Send + Sync {
    fn venue(&self) -> VenueId;
    fn artifact(&self) -> &ArtifactRef;

    fn is_open(&self, at: OffsetDateTime) -> bool;

    fn session_for(&self, at: OffsetDateTime) -> Option<Session>;

    fn sessions_between(
        &self,
        from: OffsetDateTime,
        to: OffsetDateTime,
    ) -> Vec<Session>;

    /// Bar boundaries at a given resolution, honoring breaks and early
    /// closes. This is what the backtest iterates; it never iterates
    /// naive fixed-width time buckets.
    fn bar_boundaries(
        &self,
        session: &Session,
        resolution: BarResolution,
    ) -> Vec<OffsetDateTime>;
}

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct Session {
    pub venue: VenueId,
    pub date: Date,
    pub open: OffsetDateTime,
    pub close: OffsetDateTime,

    pub breaks: Vec<(OffsetDateTime, OffsetDateTime)>,
    pub early_close: bool,
    /// Unplanned halts and interruptions, sourced separately and merged.
    pub interruptions: Vec<Interruption>,
```

### 12.5 Tokenizer Codebooks as Pinned Artifacts

v0.3 §3.1 defines `SeriesTokenizer` and correctly requires `reconstruction_mae` disclosure. v1.0 adds the artifact discipline and one validation rule drawn directly from the Kronos operational documentation: tokenizer and model are a matched pair, and a mismatched pair loads without an obvious error while producing degraded output. That is the worst failure mode available, so it is closed structurally.

```rust
/// Registered pairing of a model artifact and the tokenizer codebook it
/// was trained against. Loading a model with an unpaired codebook is a
/// hard deny, not a warning, because the failure mode is silent
/// degradation rather than an error.
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct TokenizerBinding {
    pub model_id: ModelId,
    pub model_version: SemanticVersion,
    pub codebook: ArtifactRef,
    pub max_context_tokens: usize,
    pub modalities: Vec<SeriesModality>,
    /// Disclosed alongside every forecast per v0.3 §3.1.
    pub reconstruction_mae: f64,
}

impl ModelRegistry {
    /// Loads a TSFM. Fails closed on any of: license class violation,
    /// tokenizer mismatch, context overflow, signature failure,
    /// or pretraining-cutoff violation against an active backtest window.
    pub fn load_tsfm(
        &self,
        model_id: &ModelId,
        ctx: &DeterminismContext,
        window: Option<&BacktestWindow>,
    ) -> Result<Arc<dyn TsfmRuntime>, RegistryError> {
        let entry = self.lookup(model_id)?;

        // 1. Commercial license gate. See §8 amendment one.
        if self.profile.is_commercial()
            && entry.license_class == ArtifactLicenseClass::NonCommercial
        {
            return Err(RegistryError::NonCommercialArtifact {
                model_id: model_id.clone(),
                license: entry.license_spdx.clone(),
            });
        }

        // 2. Signature verification over content hash, dual scheme.
        self.verify_signature(&entry.artifact)?;

        // 3. Tokenizer pairing. Silent-degradation guard.
        let binding = self.binding_for(model_id)?;
        if binding.codebook.content_hash != entry.expected_codebook_hash {
            return Err(RegistryError::TokenizerMismatch {
                model_id: model_id.clone(),
                expected: entry.expected_codebook_hash,
                found: binding.codebook.content_hash,
            });
        }

        // 4. Pretraining hygiene. v0.3 §6.1. Hard deny, logged as a
        //    security event rather than a warning.
        if let Some(w) = window {
            if entry.pretraining_cutoff >= w.start {
                self.audit.record_security_event(
                    SecurityEvent::LookaheadDenied {
                        model_id: model_id.clone(),
                        pretraining_cutoff: entry.pretraining_cutoff,
                        backtest_start: w.start,
                    },
                )?;
                return Err(RegistryError::PretrainingContamination {
                    cutoff: entry.pretraining_cutoff,
                    backtest_start: w.start,
                });
            }
        }

        // 5. Pin into the run's artifact set so it lands in the manifest.
        ctx.pinned.record_model(&entry.artifact);

        self.instantiate(entry, binding)
    }
}
```

### 13.2 Lineage

v0.2 §8's `Lineage` struct is carried forward unchanged. The additions are the OpenLineage projection described in Section 6.13 and one clarification the original left implicit:

**The invalidation hash MUST include the `PinnedArtifactSet`.** v0.2 §8 hashes upstream record ids plus transform plus version. That misses calendar, codebook, and model changes, which is exactly the class of silent breakage Section 12 exists to prevent. The corrected definition:

```rust
impl Lineage {
    /// Invalidation hash. Any change to upstream records, the transform,
    /// the transform version, OR any pinned artifact changes this hash
    /// and marks every downstream record stale.
    pub fn invalidation_hash(&self, pinned: &PinnedArtifactSet) -> ContentHash {
        let mut h = blake3::Hasher::new();
        // Sorted for determinism; upstream ordering is not guaranteed.
        let mut ids: Vec<_> = self.upstream_record_ids.iter().collect();
        ids.sort_unstable();
        for id in ids {
            h.update(id.as_bytes());
        }
        h.update(self.transform_id.as_bytes());
        h.update(self.transform_version.to_string().as_bytes());
        h.update(&pinned.stable_digest());
        ContentHash(h.finalize().into())
    }
}
```

## 14. The Audit Ledger

### 14.1 The Trait

```rust
//! prismatik-audit
//!
//! Append-only, hash-chained audit ledger. "Immutable" in v0.1 §2.4 is
//! implemented here as *tamper-evident*, which is the achievable property:
//! a sufficiently privileged attacker can always alter bytes on disk, but
//! they cannot do so without breaking a hash chain that has already been
//! witnessed. The model is the same one Sigstore's Rekor uses for signing
//! events: an append-only Merkle log where inclusion and consistency are
//! provable without trusting the storage layer.

pub trait AuditLedger: Send + Sync {
    /// Append an entry. Returns its position and the new tree head.
    /// This call is on the critical path for every sensitive operation
    /// and MUST complete before the operation is considered to have
    /// happened. Audit is not fire-and-forget.
    fn append(&self, entry: AuditEntry) -> Result<AuditReceipt, AuditError>;

    /// Prove a specific entry is included under a given tree head.
    fn inclusion_proof(

        position: u64,
        head: &TreeHead,
    ) -> Result<InclusionProof, AuditError>;

    /// Prove that a later head is a consistent extension of an earlier
    /// one, meaning nothing was inserted, removed, or reordered in
    /// between. This is the check that detects retroactive editing.
    fn consistency_proof(
        &self,
        from: &TreeHead,
        to: &TreeHead,
    ) -> Result<ConsistencyProof, AuditError>;

    /// Current signed tree head.
    fn signed_head(&self) -> Result<SignedTreeHead, AuditError>;

    /// Full verification of the local log. Runs at startup and in CI.
    fn verify_all(&self) -> Result<VerificationReport, AuditError>;
}

    pub actor: Actor,          // User | System | Ai | Plugin | Sidecar

    pub subject: SubjectRef,
    pub outcome: Outcome,      // Allowed | Denied | Failed
    /// Hash of the previous entry. Chains the log.
    pub prev_hash: ContentHash,
    /// Redacted payload. Secrets never enter the ledger, and the
```

### 14.2 Audit as the Write Path

This is the barter-rs derived inversion described in Section 6.8, and it is the design decision that makes I7 cheap instead of expensive.

Conventional design: the application mutates state, then writes an audit record describing what it did. The audit record can be forgotten, can disagree with the state, and is trusted only because everyone agrees to trust it.

PRISMATIK design: **the audit entry is the write.** State is a projection.

```text
                      ┌──────────────────────┐
  command  ──────────▶│  Policy + Risk gate  │
                      └───────────┬──────────┘
                                  │ (allowed | denied, BOTH are appended)
                      ┌───────────▼──────────┐
                      │   AUDIT LEDGER       │  ◀── the only write path
                      │   append-only Merkle │
                      └───────────┬──────────┘
                                  │ replay
              ┌───────────────────┼───────────────────┐
              ▼                   ▼                   ▼
      PortfolioState        OrderState          UI Replica
       (projection)        (projection)        (projection)
```

Three consequences follow, all of them good.

1. A denied action is recorded with the same fidelity as an allowed one. Most audit systems record what happened; this one records what was attempted, which is where the interesting security signal lives.
2. Any projection can be rebuilt from the ledger. A corrupted portfolio table is a recoverable inconvenience rather than a data loss event.
3. A projection that disagrees with the ledger is *detectable*, because the ledger is authoritative and replay is cheap. Run reconciliation on startup and after every broker interaction.

The cost is a synchronous append on the sensitive path. For a single user desktop application with sub millisecond local appends this is not a meaningful latency budget. For the Team Cloud profile, batch appends with a bounded window and treat the window as an explicit, documented risk in the threat model.

### 14.3 What Gets Audited

Not everything. An audit log that records every read is an audit log nobody reads.

| Category | Audited | Rationale |
|---|:---:|---|
| Order intent created, risk evaluated, approved, submitted, filled, cancelled | yes | Regulatory and forensic core |
| Risk check denial | yes | The most valuable signal in the log |
| Live execution enablement, step-up auth | yes | Privilege change |
| Credential added, rotated, removed (never the value) | yes | Privilege change |
| Model promoted, retired, or loaded with a policy exception | yes | Governance |
| Pretraining contamination denial | yes | Security event per v0.3 §6.1 |
| Plugin installed, granted capabilities, or denied | yes | Supply chain |
| MCP server approved or invoked with Sensitive trust | yes | AI boundary |
| Manifest signed or verification failed | yes | Reproducibility integrity |
| Data export, backup created, backup restored | yes | Exfiltration signal |

| ReadOnly AI tool calls | metrics only | Volume; counted not logged |

### 14.4 Verifiable Research Artifacts

v0.1 §37.5 files signed result bundles as a future advancement. It is not future; the manifest already implies it. Section 14 delivers it now, at essentially zero marginal cost, because a manifest plus an audit inclusion proof plus a dual signature *is* a verifiable research artifact.

A PRISMATIK research bundle is a tarball containing the manifest, the pinned artifact references with their hashes, the metrics, the audit inclusion proof for the run, and the dual signature. A third party with the public verification key and the published manifest schema can verify the bundle without PRISMATIK, without network access, and without trusting Mythos Systems. Publishing the manifest schema under Apache-2.0, per Section 8 amendment three, is what makes that verification possible by someone who does not have the product.

That is a defensible, differentiating, and genuinely uncommon capability, and it costs one schema publication.

### 15.1 Six Layers, Restated with Ownership

| Intelligence | Model output, scores, forecasts, embeddings | versioned | Parquet plus LanceDB | 3 years |
| Presentation | User scoped materialized views | disposable | SQLite | Cache, evictable |

**Raw is append only and never rewritten, including when the provider was wrong.** A provider correction creates a new raw record with its own `retrieved_at` and a supersession link. This is what makes "what did we know at 09:31" answerable, which is the question that matters in any post trade investigation.

### 15.2 Engine Selection Rationale

Six engines is a lot. Each earns its place or it goes.

- **SQLite.** Operational state, task graph persistence, online feature serving, presentation cache. Ships with the desktop. Zero operations. This is the desktop's spine.
- **DuckDB plus DataFusion.** Analytical queries over Parquet without a server. DuckDB for interactive user queries, DataFusion for programmatic plan construction inside the strategy DSL. They overlap; the overlap is accepted because the use cases differ in who writes the query.
- **Parquet plus Arrow.** The durable columnar substrate. Every layer above raw is Parquet. Arrow is the in memory interchange between Rust, DuckDB, LanceDB, and the Python sidecars, which means a calibration sidecar receives zero copy Arrow rather than serialized JSON.
- **LanceDB.** Embeddings and the analog index. Justified in Section 6.1.
- **PostgreSQL.** Multi user identity, RBAC, tenancy, workspace sharing. Cloud and enterprise only. A desktop user has one identity and needs none of this.
- **ClickHouse.** Tick level and options print scale aggregation. Cloud and enterprise only. Introduced at Phase 3 when options flow volume justifies it, not before.
- **NATS JetStream.** Durable cross service events. Cloud and enterprise only.

**The `observation_delay` field is the single highest value line in this struct.** It is the difference between a feature store and a look ahead bug generator. 13F holdings, Commitments of Traders reports, and restated fundamentals all have publication lags measured in days to weeks, and a naive `event_time <= as_of` join treats them as observable at the moment they describe rather than the moment they were published. Encoding the delay in the view definition means every consumer inherits the correct behavior.

Property test, in Section 27.3: for a random view, entity, and instant, assert that no returned value has `event_time + observation_delay > as_of`. This test has caught the bug in every feature store the author has seen it applied to.

### 17.2 The Baseline Ladder Is Not Optional

v0.1 §12.2 mandates "start simple and earn complexity" and v0.3 §9 reiterates it. v1.0 makes it a registration precondition rather than a cultural aspiration.

**A model MUST NOT be promoted to any user facing surface unless the registry holds an out of sample comparison against all lower rungs of the ladder, and the candidate wins on both discrimination and calibration.**

| Rung | Family | Must beat |
|---|---|---|
| 0 | Naive persistence, random walk, unconditional mean | nothing, this is the floor |
| 1 | Classical statistical (ARIMA, GARCH, EWMA volatility) | rung 0 |
| 2 | Regularized linear, gradient boosted trees | rungs 0 and 1 |
| 3 | Task specific neural network | rungs 0 through 2 |
| 4 | TSFM, zero shot or fine tuned | rungs 0 through 3 |
| 5 | Ensemble | every constituent, individually |

Winning on discrimination alone is insufficient. A model that ranks better but is worse calibrated is a model that will be trusted more than it deserves, which is the precise failure v0.1 §35.3 identifies as a top risk. The registry enforces both.

### 17.3 Calibration

Closes G03. This is where MAPIE and crepes land.

```rust
/// Turns raw model output into intervals with a stated, tested coverage
/// property. No model output reaches a user surface without one.
///
/// Method: split conformal prediction, with Adaptive Conformal Inference
/// (ACI) as the default for time series. ACI is chosen deliberately over
/// standard split conformal because standard conformal's coverage
/// guarantee assumes exchangeability, and financial returns are not
/// exchangeable. ACI adjusts the target quantile online in response to
/// realized coverage error and does not require exchangeability, which
/// makes it the only defensible default here.
pub trait Calibrator: Send + Sync {
    fn method(&self) -> CalibrationMethod;

    /// Fit on a held-out conformalization set. Never on training data,
    /// never on the evaluation set.
    fn conformalize(
        &mut self,
        predictions: &PredictionBatch,
        realizations: &RealizationBatch,
        ctx: &DeterminismContext,
    ) -> Result<CalibrationRecord, CalibrationError>;

    /// Apply to a raw prediction, producing a calibrated interval.
    fn calibrate(
        &self,
        raw: &RawPrediction,
        target_coverage: Coverage,
    ) -> Result<CalibratedPrediction, CalibrationError>;

    /// Online update as realizations arrive. ACI's coverage correction.
    fn update(
        &mut self,
        observed: &RealizationBatch,
    ) -> Result<CoverageDrift, CalibrationError>;
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum CalibrationMethod {
    /// Standard split conformal. Only valid where exchangeability is
    /// defensible, which for market data is essentially never. Retained
    /// for cross-sectional (non-temporal) tasks only.
    SplitConformal,
    /// Ensemble batch prediction intervals. Bootstrap-based, no data
    /// splitting, suited to short series.
    EnbPI,
    /// Adaptive Conformal Inference. DEFAULT for all temporal forecasts.
    AdaptiveConformal { learning_rate: f64 },
    /// Mondrian / regime-conditioned conformal. Separate calibration per
    /// category, which for PRISMATIK means per volatility regime. Use
    /// when a single global interval is too wide to be useful in calm
    /// regimes and too narrow in stressed ones.
    MondrianConformal { categorizer: CategorizerId },
    /// Isotonic or Platt scaling for classification probabilities.
    ProbabilityScaling(ScalingKind),
}

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct CalibrationRecord {
    pub method: CalibrationMethod,
    pub conformalized_on: TimeWindow,
    pub sample_size: usize,
    /// Realized coverage per nominal level. The honesty check: nominal
    /// 90% must actually contain the realization about 90% of the time.
    pub coverage_curve: Vec<(Coverage, RealizedCoverage)>,
    /// Mean interval width. Coverage is trivially achievable with
    /// infinite width, so width is reported alongside it, always.
    pub mean_interval_width: f64,
    /// Proper scoring rules. Lower is better.
    pub pinball_loss: f64,
    pub crps: f64,
    /// Coverage broken down by regime. A model well calibrated on
    /// average and badly calibrated in stress is worse than useless,
    /// because stress is when the user is paying attention.
    pub per_regime_coverage: Vec<(RegimeLabel, RealizedCoverage)>,
    pub calibrator_artifact: ArtifactRef,
    pub computed_at: OffsetDateTime,
}
```

The sidecar contract: `services/sidecars/calibration/` receives an Arrow table over a local socket, runs MAPIE for ACI and EnbPI and crepes for Mondrian, and returns a `CalibrationRecord`. It never sees credentials, never writes to the data plane, and its output is stamped with provenance exactly like a provider payload.

**UI consequence, and it is the whole point.** Every forecast surface shows the coverage curve. Not a confidence percentage in isolation. A user seeing "90% interval" alongside "realized coverage 72% over the last 500 observations, and 51% in high volatility regimes" understands something true. A user seeing "90% confidence" alone does not. This is Invariant I2 made visible.

## 18. Strategy Plane

### 18.1 The Three Authoring Modes and One IR

v0.1 §11.1 lists four authoring modes (visual builder, DSL, Python, Rust SDK). v0.2 §1.1 defines `StrategyIR` as the convergence point. v1.0 changes one thing: **Python is not an authoring mode for executable strategies.** It is a research mode.

The reason is Invariant I3. A Python strategy executing inside a backtest brings an entire interpreter's worth of ambient non determinism into the deterministic core: dict ordering across versions, floating point library differences, C extension behavior, and an import graph nobody pinned. Every mitigation for that is more expensive than the alternative.

The alternative: Python authors strategies by *emitting StrategyIR*, in the research sidecar, and the IR then executes on the Rust runtime exactly like every other strategy. Researchers keep their tooling. The runtime keeps its guarantees. This is a strictly better trade and it costs a JSON schema.

| Mode | Produces | Executes where | Deterministic |
|---|---|---|:---:|
| Visual builder | StrategyIR via codegen | Rust runtime | yes |
| Strategy DSL | StrategyIR via compiler | Rust runtime | yes |
| Rust SDK | StrategyIR plus native impl | Rust runtime | yes |
| **Python** | **StrategyIR via emitter, in sidecar** | **Rust runtime** | **yes** |
| WASM plugin | StrategyIR plus WASM module | Plugin host | yes, host controlled |

### 18.2 DSL Implementation

Closes G11. v0.1 §11.1 mandates that the DSL compile to a typed IR and stops there.

**Ruling: a purpose built, non Turing complete expression language, parsed with a hand written recursive descent parser over a `logos` lexer, compiling to DataFusion logical plans for data access and to `StrategyIR` rule trees for logic.**

Non Turing complete is deliberate and the most important word in that sentence. A strategy language with unbounded loops needs a fuel meter, a timeout, and a story about what a half executed strategy means for portfolio state. A language where every expression terminates by construction needs none of those, and there is no strategy in PRISMATIK's scope that requires unbounded iteration. Rejecting general purpose embedded interpreters (`rhai`, `steel`, Lua) is therefore a feature and not a limitation.

```rust
/// Compiler output. Every path into the runtime produces this, and the
/// runtime accepts nothing else.
pub struct CompilationResult {
    pub ir: StrategyIR,
    /// Data access compiled to a DataFusion plan. Point-in-time
    /// enforcement is a plan rewrite rule applied here, so a strategy
    /// author cannot bypass it by writing the query differently.
    pub data_plan: LogicalPlan,
    /// Capabilities INFERRED from the source, then intersected with the
    /// capabilities the user is permitted to grant. A strategy that
    /// reads option chains gets `can_read_options`; it cannot ask for
    /// `can_access_network` because the language has no network verb.
    pub inferred_capabilities: StrategyCapabilities,
    pub diagnostics: Vec<Diagnostic>,
    pub source_hash: ContentHash,
    pub compiler_version: SemanticVersion,
}
```

The capability inference in that struct is worth dwelling on. Capabilities are not declared by the strategy author and then checked; they are *derived from what the source actually references* and then intersected with what the user is allowed to grant. A strategy cannot over request, and it cannot under declare. This is Invariant I4 implemented at compile time rather than at run time.

## 19. Risk and Execution Plane

### 19.1 Pre Trade Checks

v0.2 §2.2 catalogues thirteen. v1.0 adds three and states the ordering rule.

| Check | Severity | Rule |
|---|---|---|
| `max_position` | HardDeny | Position notional above policy limit |
| `max_premium` | HardDeny | Premium at risk above account fraction |
| `max_account_loss` | HardDeny | Realized plus unrealized loss above daily limit |
| `sector_concentration` | HardDeny | Sector exposure above policy |
| `account_permissions` | HardDeny | Account not enabled for asset or strategy type |
| `market_status` | HardDeny | Market closed, halted, or session not permitted |
| `stale_data` | HardDeny | Any input older than policy max age (Invariant I6) |
| `duplicate_order` | HardDeny | Idempotency key collision or same contract in window |
| **`adjusted_contract`** | **HardDeny for automation** | **Option contract carries an OCC adjustment memo** |
| **`calendar_mismatch`** | **HardDeny** | **Pinned calendar disagrees with venue live status** |
| **`model_suppressed`** | **HardDeny** | **Intent cites a model currently suppressed by drift** |
| `correlation_cluster` | SoftWarn | Portfolio correlation raised above threshold |
| `event_proximity` | SoftWarn | Earnings or macro event within N hours |
| `spread_width` | SoftWarn | Bid ask spread above policy |
| `liquidity_volume` | SoftWarn | 30 day average volume below threshold |
| `open_interest` | SoftWarn | Open interest below threshold |

**Ordering rule, which v0.2 leaves unspecified.** Checks evaluate in a fixed, declared order: cheapest and most deterministic first, and all HardDeny checks before any SoftWarn. Two reasons. First, a deny should not depend on how far evaluation happened to get. Second, a fixed order makes the audit record comparable across runs, which matters when someone asks why an identical intent was denied on Tuesday and allowed on Wednesday.

All checks are recorded, including those that passed, per v0.2. The evidence chain for a denial includes the portfolio snapshot at evaluation time, so a denial is explainable months later without reconstructing state.

### 19.2 Execution Boundary

v0.1 §17.5 and v0.2 §3, carried forward, with one clarification that closes a real gap.

**The unknown result problem.** `BrokerGateway::submit` can return three outcomes, not two: success, failure, and *unknown*. Unknown is the interesting one. A timeout, a dropped connection, or a 5xx after the request left the process leaves local state and broker state potentially divergent, and the naive response, retrying, is how duplicate orders happen.

```rust
#[derive(Clone, Debug)]
pub enum SubmissionResult {
    Accepted { broker_order_id: BrokerOrderId, accepted_at: OffsetDateTime },
    Rejected { reason: BrokerRejection },
    /// The request may or may not have reached the broker. The system
    /// MUST NOT retry blindly. It MUST reconcile, and until
    /// reconciliation completes the intent is quarantined: no further
    /// intents for the same instrument are admitted.
    Unknown { idempotency_key: IdempotencyKey, last_known_state: LocalOrderState },
}
```

The reconciliation path is: quarantine the instrument, call `BrokerGateway::reconcile`, compare the returned delta against local belief, append the resolution to the audit ledger, and only then release the quarantine. If reconciliation itself fails, the instrument stays quarantined and the user is notified. Failing loudly and stopping is correct here; guessing is not.

```rust
fn hardened_engine() -> Result<Engine, PluginError> {
    let mut cfg = Config::new();

    // Cranelift only. Winch is PROHIBITED: RUSTSEC-2026-0095 documented a
    // sandbox-escaping memory access in the Winch backend.
    cfg.strategy(Strategy::Cranelift);

    // showed an over-read in f64.copysign that is contained by guard
    // pages and becomes an uncaught segfault or out-of-sandbox load

    cfg.signals_based_traps(true);
    cfg.guard_before_linear_memory(true);

    // Fuel metering: bounded execution without relying on a watchdog.
    cfg.consume_fuel(true);

    // Epoch interruption: bounded wall time even for non-fuel-consuming
    // loops in host calls.
    cfg.epoch_interruption(true);

    // No ambient nondeterminism reaches guest code.
    cfg.wasm_threads(false);
    cfg.wasm_simd(true);          // deterministic; permitted
    cfg.wasm_relaxed_simd(false); // NOT deterministic; prohibited
    cfg.wasm_reference_types(true);
```

## 24. Security Architecture

v0.1 §23 and §24 are comprehensive and carry forward. Three additions.

### 24.1 Tauri Capability Policy

The capability policy is the enforcement point for the WebView boundary. Default deny, explicit allow, no wildcards.

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "prismatik-main",
  "description": "Main window. Default-deny capability set.",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "core:window:allow-start-dragging",
    { "identifier": "shell:allow-open",
      "allow": [{ "url": "https://docs.mythossys.io/**" }] }
  ]
}
```

`fs`, `http`, `process`, and `shell:execute` are absent and MUST remain absent. Every filesystem and network operation goes through a registered Tauri command in the trusted core, where it is validated, authorized, rate limited, and audited. A WebView that can open a socket is a WebView that can exfiltrate a portfolio.

Content Security Policy is strict, with no `unsafe-inline`, no `unsafe-eval`, and no remote script origins. Svelte's compiled output does not require any of them.

### 24.2 Key Hierarchy

Closes G18. v0.1 §21.3 mandates local encryption without specifying a hierarchy.

```text
  OS Keychain / Secure Enclave / TPM
            │
            ▼
   Device Root Key  (never leaves the keystore, non-exportable)
            │
   ┌────────┼──────────────┬───────────────────┬──────────────────┐
   ▼        ▼              ▼                   ▼                  ▼
 Data     Credential    Manifest            Audit             Backup
 Key      Key           Signing Key         Signing Key       Key
 (AES-    (broker and   (Ed25519 +          (Ed25519 +        (derived from
  256-     provider      ML-DSA)             ML-DSA)           passphrase via
  GCM)     secrets)                                            Argon2id)
```

Rules, each of which exists because its violation is a common and expensive mistake:

- The device root key is generated in and never leaves the OS keystore. There is no export path, including for support.
- Backup keys derive from a user passphrase through Argon2id with parameters recorded in the backup header, so a future version can verify a backup produced by an older one.
- **Signing keys are never derived from `Entropy`.** The Determinism Kernel is reproducible by construction, and reproducible key material is not key material. Cryptographic randomness comes from the OS CSPRNG through `prismatik-security`, which is why `Entropy::fill_bytes` carries an explicit prohibition in its doc comment.
- Rotation is supported for every key except the device root, which is rotated by re enrollment.

### 24.3 Post Quantum Posture

v0.1 §24 carries forward unchanged in substance. v1.0 makes one thing normative that v0.1 left as a phase: **dual signature from Phase 0, not Phase 8.**

Every manifest, artifact, and audit tree head carries both an Ed25519 signature and an ML-DSA (FIPS 204) signature. Verification requires both to pass.

The rationale is not cryptographic urgency. It is migration cost. A signature scheme retrofitted onto an existing corpus of signed manifests requires re signing everything, which requires the original signing keys, which requires having planned for it. Paying the extra bytes and the extra verification microseconds from the first manifest is cheaper by an order of magnitude than the alternative, and PRISMATIK's manifests are explicitly designed to be verified years after creation.

### 25.3 Release and Update

Artifacts are signed with cosign keyless signing, which issues short lived certificates from an OIDC identity through Fulcio and records the signing event in the Rekor transparency log. SLSA provenance is generated by the build workflow.

**The updater verifies provenance before installing, and this is not optional.** Generating provenance without verifying it at the point of consumption is a logging exercise, not a security control. The PRISMATIK updater checks the cosign signature, checks the SLSA provenance against the expected builder identity and source repository, checks the artifact hash, and refuses to install on any failure. A refused update is a supported state with a clear user message; a silently installed unverified update is not.

## 26. Observability

v0.1 §26 carries forward. One addition and one constraint.

**Addition: determinism telemetry.** Every run emits its `PinnedArtifactSet` digest, root seed, and clock kind as span attributes. When a support case says results changed, the first diagnostic is a digest comparison, which resolves most such cases in seconds rather than hours.

**Constraint: tracing must not break determinism.** Span ids and trace ids are generated from `Entropy`, not from `rand::thread_rng`, and timestamps come from `Clock`. Otherwise the trace comparison method that verifies determinism in the DST suite compares traces that differ for reasons unrelated to the code under test, and the whole verification approach collapses. This is a small detail with a large blast radius.

### 27.2 Deterministic Simulation Suite

The mechanism from Section 6.9, operationalized.

```rust
/// Author:  Aaron Stovall
/// Date:    2026-07-24
/// Version: 1.0.0
/// Purpose: Verify Invariant I3 (determinism under seed) across the full
///          ingest -> normalize -> feature -> backtest -> manifest path,
///          under simulated network hardship, clock skew, and injected
///          failures.
///
/// Method:  Run the same seed twice under madsim. Capture TRACE-level
///          logs from both runs. Assert byte equality. A divergence is a
///          determinism leak somewhere in the process, including in a
///          transitive dependency, and the failing seed is printed so it
///          reproduces locally without modification.
///
/// Run:     cargo test --features dst --test dst_replay -- --nocapture
///          PRISMATIK_DST_SEEDS=1000 cargo test --features dst ...
#[cfg(feature = "dst")]
#[madsim::test]
async fn dst_replay_is_byte_identical() {
    let seed_count: u64 = std::env::var("PRISMATIK_DST_SEEDS")
        .ok()
        .and_then(|s| s.parse().ok())
        .unwrap_or(64);

    for seed in 0..seed_count {
        let first = run_full_pipeline_capturing_trace(seed).await;
        let second = run_full_pipeline_capturing_trace(seed).await;

        assert_eq!(
            first.trace_digest, second.trace_digest,
            "determinism leak at seed {seed}: trace digests differ.\n\
             first divergence at line {}\n\
             reproduce with: PRISMATIK_DST_SEEDS=1 PRISMATIK_DST_START={seed} \
             cargo test --features dst --test dst_replay",
            first.first_divergence_line(&second).unwrap_or(0),
        );

        assert_eq!(
            first.manifest_hash, second.manifest_hash,
            "manifest hash differs at seed {seed} despite matching traces; \
             manifest construction itself is nondeterministic",
        );
    }
}
```

The second assertion catches a subtle and real failure: traces can match while manifest construction still varies, for example through map iteration order when serializing the pinned artifact set. Both assertions are needed.

### 27.3 High Value Property Tests

## 32. Definition of Done

A change is complete only when every applicable line is true. This is the checklist, and it is not advisory.

**Every change**

- Compiles with zero warnings under `clippy -D warnings`.
- Adds no `Instant::now`, `SystemTime::now`, `thread_rng`, or default hasher map outside the allowlist.
- Has unit tests, and property tests where an invariant exists.
- Has structured `tracing` instrumentation with span attributes, not string interpolation.
- Handles every error path explicitly. No `unwrap` outside tests. No `expect` without a proof comment.
- Updates generated bindings if it touches the IPC surface, with the drift gate green.

**Any change touching data, models, or execution**

- Preserves provenance and lineage on every derived record.
- Passes the golden manifest corpus, or regenerates it with a changelog entry explaining the semantic change.
- Passes `dst_replay_suite`.
- Adds an audit entry if it performs a sensitive operation, and the entry appends before the operation is considered complete.
- Adds or updates the relevant pre trade check if it introduces a new risk surface.

**Any change adding a dependency**

- Has a signed component manifest in `prismatik-oss-registry`.
- Passes `cargo deny` and, if in the trusted core path, `cargo vet`.
- Has an assigned integration mode and a recorded trust boundary assessment.
- Has license notices resolvable by the notice generator.

**Any change touching a public contract**

- Has an ADR if it is a decision rather than an implementation.
- Versions the schema and states the compatibility expectation.
- Updates the API documentation and, for a breaking change, the migration note.

### Verification Protocol

A third party verifies a bundle with `prismatik verify bundle.tar.zst`, which:

1. Checks both signatures over the canonical serialization of the manifest. **Both must pass.** A single valid signature is a failure, not a partial success.
2. Checks every `pinned_artifacts` hash against the bundled or locally resolvable artifacts.
3. Checks the audit inclusion proof against the published tree head.
4. Checks `environment.sbom_hash` and `slsa_provenance` against the release attestation.
5. Optionally re executes the run and asserts `outputs.result_bundle_hash` matches.

Steps 1 through 4 require no network access and no PRISMATIK installation beyond the standalone verifier, which is the property that makes the artifact genuinely verifiable rather than merely signed.

## Appendix D. Glossary of v1.0 Terms

| Term | Meaning |
|---|---|
| Determinism Kernel | The crate set owning time, entropy, ordering, identity, and pinned artifacts |
| Pinned Artifact Set | The complete set of non record inputs that could alter a run's output |
| Content addressed | Identified by the BLAKE3 hash of its bytes, so identity and integrity are the same check |
| Tamper evident | Alterable in principle, but not without breaking a witnessed hash chain |
| Projection | A read model rebuilt by replaying the audit ledger |
| Observation delay | The lag between an event's timestamp and the moment it became publicly observable |
| Conformal prediction | Distribution free interval construction with finite sample coverage guarantees |
| ACI | Adaptive Conformal Inference, an online variant valid without exchangeability |
| Mondrian conformal | Conformal calibration computed separately per category, for PRISMATIK per volatility regime |
| Baseline ladder | The rung ordering a model must beat, out of sample, on both discrimination and calibration, before promotion |
| DST | Deterministic Simulation Testing |
| Golden manifest corpus | Committed manifests whose outputs CI re verifies on every run |
| Trust boundary | A point where a defect would silently invalidate a reproduction, a risk check, or an audit claim |
