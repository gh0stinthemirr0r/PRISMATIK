## 0. Purpose

This document specifies the **design tokens, component library inventory, interaction patterns, evidence-drawer UX, and chart-theming contract** for PRISMATIK's Svelte 5 / SvelteKit frontend. It exists to keep the UI coherent across waves and to make sure the seven invariants are visible in the interface — not just enforced in the backend.

The cardinal UX rule: **the user must be able to see what the system knows, how confident it is, and what would change its mind.** Evidence-chaining, calibration, staleness, and uncertainty are first-class UI concerns, not decorative badges.

---

## 1. Stack and Discipline

- **Framework:** Svelte 5 (runes) / SvelteKit, `adapter-static` for the Tauri shell.
- **Type bindings:** `packages/api-client/` generated by tauri-specta (NEVER hand-edited).
- **Charts:** Lightweight Charts (financial), Apache ECharts (general), Perspective (streaming grids), wgpu (GPU surfaces — volatility surfaces, MC paths).
- **Styling:** CSS variables (design tokens) for theming; no CSS-in-JS for performance and SSR-friendliness.
- **State:** Svelte stores; derived stores for evidence resolution.
- **Accessibility:** WCAG 2.2 AA; reduced-motion support mandatory; keyboard navigation mandatory for every interactive surface.

## 4. The Evidence Drawer (Invariant I1 Made Visible)

Every conclusion surface (opportunity card, forecast, score, ranking, alert) MUST render an `EvidenceBadge` that opens the evidence drawer on click.

```svelte
<!-- EvidenceBadge.svelte -->
<script lang="ts">
  import type { EvidenceRef } from '@prismatik/api-client';

  let { evidence, contradictions, blindSpots, asOf }: {
    evidence: EvidenceRef[];
    contradictions: EvidenceRef[];
    blindSpots: BlindSpot[];
    asOf: string;
  } = $props();
</script>

<button class="evidence-badge" onclick={openDrawer}>
  <span class="count">{evidence.length}</span>
  {#if contradictions.length > 0}
    <span class="contradictions" title="{contradictions.length} contradicting">
      ⚠ {contradictions.length}
    </span>
  {/if}
</button>
```

**The drawer shows:**
1. Every evidence item with provider, retrieved_at, event_time, quality score.
2. Contradictions tab — explicitly rendered even if empty. "Searched and found none" is rendered distinctly from "did not search" (per v1.0 §13.1).
3. Blind spots tab — what we don't know.
4. As-of timestamp — when this conclusion was valid.
5. Each item links to its raw record (resolvable via `resolve_evidence`).

**Empty contradictions ≠ unrendered contradictions.** Per Invariant I1, an opportunity with zero contradictions after a genuine search is reported as "none found" — a weaker claim than "none exist." The UI distinguishes.

## 5. The Calibration Ribbon (Invariant I2 Made Visible)

Every forecast surface MUST render the calibration ribbon (v1.0 §17.3, §21). The ribbon visualizes realized coverage against nominal coverage.

```svelte
<!-- CalibrationRibbon.svelte -->
<script lang="ts">
  let { coverageCurve, meanWidth, perRegime }: {
    coverageCurve: Array<{ nominal: number; realized: number }>;
    meanWidth: number;
    perRegime: Array<{ regime: string; realized: number }>;
  } = $props();
</script>

<div class="calibration-ribbon">
  <!--
    Solid band = realized coverage.
    Dashed outline behind = nominal coverage.
    When well-calibrated, the two coincide and the chart is unremarkable.
    When not, the divergence is the first thing the eye lands on.
  -->
</div>
```

The visual logic: when a model is well calibrated, the realized band sits inside the nominal outline and the chart is boring. When it isn't (e.g. realized 72% vs nominal 90%), the divergence is the dominant visual element.

Per-regime coverage is rendered alongside the global — a model well calibrated on average and badly calibrated in stress is worse than useless, because stress is when the user is paying attention.

## 6. The Stale-Data Marker (Invariant I6 Made Visible)

Every surface that displays data with a timestamp MUST render a stale marker when the data exceeds the policy staleness threshold.

```svelte
<!-- StaleDataMarker.svelte -->
<script lang="ts">
  let { eventTime, maxAge }: { eventTime: string; maxAge: number } = $props();
  let ageMs = $derived(Date.now() - new Date(eventTime).getTime());
  let isStale = $derived(ageMs > maxAge);
</script>

{#if isStale}
  <span class="stale-marker" style="color: var(--color-stale)">
    ⚠ Stale ({formatDuration(ageMs)})
  </span>
{/if}
```

The marker is colored with `--color-stale` (a distinct amber, not red — stale data isn't necessarily wrong, just uncertain). For pre-trade surfaces (Wave 4+), staleness is a hard deny, not a warning — the order ticket is disabled and shows the deny reason.

## 7. The Uncertainty Contract in UI

Per v1.2 §3.13 (clean-room from prism-insight) and v1.0 §20.2: AI-generated conclusions surface uncertainty structurally. The `AiResponse` type carries:
- `uncertainty: UncertaintyStatement` (required)
- `contradictions: EvidenceRef[]` (required, possibly empty)
- `suggested_verification: VerificationStep[]` (required)

The UI renders all three. An AI response that omits any of them is treated as a backend bug, not a UI nicety.

## 8. The Wallet-Sourced Cost Basis Badge (Wave 4)

Positions with `avg_cost_source: 'wallet'` MUST be visibly marked (Wave 4 DoD criterion 7). The `CostBasisBadge` renders next to P&L values derived from a wallet basis:

```svelte
{#if position.avg_cost_source === 'wallet'}
  <CostBasisBadge>
    Reconstructed from order history (no broker cost basis)
  </CostBasisBadge>
{/if}
```

Crypto spot via CCXT frequently has no real cost basis; you are synthesizing it. The user MUST see this.

## 9. Chart Theming Contract

Every chart backend (Lightweight Charts, ECharts, wgpu, Perspective) consumes the design tokens via a `ChartTheme` adapter:

```typescript
// packages/chart-contracts/theme.ts
export interface ChartTheme {
  background: string;
  text: string;
  grid: string;
  up: string;
  down: string;
  // ... etc, mapped from CSS variables
}

export function chartThemeFromTokens(): ChartTheme { /* ... */ }
```

When the user switches theme (light/dark), every chart re-themes without remounting. This requires the chart backend to expose a `setTheme(theme: ChartTheme)` method; the `ChartBackend` trait (per v1.0 §21) defines this.

## 10. Interaction Patterns

### 10.1 Command Palette (Cmd+K)

- Global palette; fuzzy search across commands and assets.
- Recent items pinned.
- Keyboard-only operability mandatory.

### 10.2 Drag-and-Drop Panels

- Panels draggable within `PanelGroup`.
- Layout persists per workspace via `workspace_layouts` SQLite table.
- Layout import/export as JSON.

### 10.3 Streaming Updates

- Live updates (quotes, bars) use the `listen()` API from `packages/api-client/`.
- Updates coalesce on backpressure (per `spec/IPC_CONTRACTS.md` §5.2).
- Loading and degraded states are explicit (Wave 1 DoD criterion 8).

### 10.4 Empty States

Every surface has three explicit states beyond populated:
- **Empty:** no data yet (e.g. watchlist with no assets).
- **Loading:** fetching in progress.
- **Error/Degraded:** provider failed; show last known + degradation indicator.
- **Stale:** data present but aged past threshold (per §6).
